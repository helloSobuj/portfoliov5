# Techill: অর্ডার + কাস্টমার ড্যাশবোর্ড

এটা একটা landing page, যেখানে ৫ ধাপে checkout হয়। সাথে আছে কাস্টমার ও ডেভেলপার ড্যাশবোর্ড (প্রোজেক্ট, চ্যাট, ফাইল, অর্ডার, ইনভয়েস) আর একটা অ্যাডমিন প্যানেল (ভিজিটর, আয়, অর্ডার, প্রোজেক্ট বোর্ড, প্যাকেজের দাম, টিম, কাস্টমার)। চলে সাধারণ PHP 8 + MySQL-এ, তাই cPanel-এ কোনো framework বা Composer লাগবে না।

## ফাইলগুলো

| ফাইল | কাজ |
|---|---|
| `index.html` | Landing page + checkout। শেষ ধাপে অর্ডার জমা হয়, আর না থাকলে অ্যাকাউন্টও খুলে যায় |
| `dashboard.html` | লগইন / রেজিস্টার। কাস্টমার নিজের প্রোজেক্ট আর অর্ডার দেখে, ডেভেলপার শুধু তাকে দেওয়া প্রোজেক্ট দেখে |
| `admin.html` | অ্যাডমিন প্যানেল, শুধু `admin` রোলের জন্য |
| `assets/catalog.json` | প্যাকেজ, দাম, অ্যাড-অন, টেমপ্লেট আর পেমেন্ট নম্বরের ডিফল্ট মান। অ্যাডমিন প্যানেল থেকে বদলালে সেটা ডেটাবেসে থাকে, ফাইল বদলায় না |
| `assets/api.js` | সব পেজের API client আর ভিজিটর ট্র্যাকিং। `api.php` না পেলে browser-এর ভেতরেই ডেমো মোডে চলে |
| `api.php` | JSON API (auth, অর্ডার, চ্যাট, ফাইল, আপডেট) |
| `lib.php` | DB, session, CSRF আর upload-এর helper |
| `config.php` | **ডেটাবেসের তথ্য এখানে দিন** |
| `schema.sql` | MySQL টেবিল |
| `index.php` | হোমপেজ: `index.html`-এ SEO ট্যাগ বসিয়ে দেখায় |
| `seo.php` | `robots.txt`, `sitemap.xml` আর IndexNow কী-ফাইল |
| `install.php` | ইনস্টলার: সার্ভার চেক, ডেটাবেস সংযোগ, প্রথম অ্যাডমিন আর `config.php` তৈরি করে, তারপর নিজেকে মুছে ফেলে। আপডেটের সময় আবার আপলোড করলে অ্যাডমিন লগইন করে ডেটাবেস আপডেট করা যায় |
| `uploads/` | আপলোড করা ফাইল থাকে, `.htaccess` দিয়ে সরাসরি খোলা বন্ধ |
| `media/` | প্রোফাইল ছবি আর টেমপ্লেটের ছবি। এগুলো সাইটে দেখাতে হয় তাই খোলা, তবে `.htaccess` শুধু সার্ভারের বানানো ছবি (`.webp/.jpg/.png`) খুলতে দেয়। ফোল্ডারটা writable (755) রাখুন |

## cPanel-এ ইনস্টল (ইনস্টলার দিয়ে, ৫ মিনিট)

1. **ডেটাবেস বানান:** cPanel → *MySQL® Databases* থেকে একটা ডেটাবেস আর একটা ইউজার বানান। *Add User To Database* থেকে ইউজারকে ডেটাবেসে **ALL PRIVILEGES** দিন।
2. **ফাইল আপলোড:** *File Manager* → `public_html` (বা সাবফোল্ডার) → zip আপলোড করে **Extract** করুন। `config.php` বদলাতে হবে না।
3. **ইনস্টলার খুলুন:** ব্রাউজারে আপনার ডোমেইন খুললেই সাইট নিজে থেকে `install.php`-এ নিয়ে যাবে (অথবা সরাসরি `https://আপনার-ডোমেইন/install.php`)। ইনস্টলার ৪ ধাপে কাজ করে:
   - **সার্ভার চেক:** PHP ভার্সন, দরকারি extension (pdo_mysql, mbstring, json, openssl, curl, fileinfo, gd), `config.php` আর ফোল্ডারে লেখার অনুমতি, ফাইল আপলোডের সীমা, HTTPS, `.htaccess` আর বাইরের ইন্টারনেট সংযোগ পরীক্ষা করে। প্রতিটা সমস্যার পাশে cPanel-এ কোথায় গিয়ে ঠিক করবেন লেখা থাকে। লাল (দরকারি) সমস্যা থাকলে এগোনো যায় না, হলুদ শুধু সতর্কতা।
   - **ডেটাবেস:** নাম, ইউজার, পাসওয়ার্ড দিন। ইনস্টলার সংযোগ আর টেবিল বানানোর অনুমতি পরীক্ষা করে, ভুল হলে সহজ বাংলায় কারণ বলে (পাসওয়ার্ড ভুল, prefix বাদ পড়েছে, অনুমতি নেই)।
   - **অ্যাডমিন:** নাম, ইমেইল, পাসওয়ার্ড (১০+ অক্ষর) আর আপলোড ফোল্ডার। আপলোড ফোল্ডার নিজে থেকে `public_html`-এর বাইরে (`/home/ইউজার/techill_uploads`) প্রস্তাব করে, না থাকলে বানিয়ে নেয়।
   - **সম্পন্ন:** সব টেবিল, অ্যাডমিন অ্যাকাউন্ট আর `config.php` তৈরি হয় (IP হ্যাশের লবণ নিজে থেকে এলোমেলো বানায়)। তারপর **ইনস্টলার নিজেকে মুছে ফেলে**।
4. `admin.html`-এ লগইন করে প্যাকেজ ও দাম, PayStation, ইমেইল আর টিম সাজান। HTTPS চালু রাখুন (cPanel → *SSL/TLS Status* → AutoSSL)।

**নিরাপত্তা:**
- ইনস্টল শেষে `install.php` মুছে যায়। হোস্টিং মুছতে না দিলে সেটা লক হয়ে থাকে: ইনস্টল করা সাইটে কেউ আবার ইনস্টল চালাতে পারে না, শুধু অ্যাডমিন লগইন করে ডেটাবেস আপডেট করা যায়। তবু তখন নিজে ফাইলটা মুছে দিন।
- `config.php`-তে লেখার অনুমতি না থাকলে ইনস্টলার পুরো config কোড দেখায়। সেটা কপি করে `config.php`-তে বসিয়ে একই তথ্য দিয়ে আবার "ইনস্টল করুন" চাপলেই হবে।
- ফাইল আপলোডের পর আর ইনস্টলের আগের সময়টুকুতে যে কেউ `install.php` খুলতে পারে, তাই আপলোড করেই ইনস্টল শেষ করে ফেলুন।

phpMyAdmin পছন্দ করলে `schema.sql` import করা যায়, তবে অ্যাডমিন আর config বানাতে ইনস্টলার চালানোই সহজ।

### আগের ভার্সন থেকে আপডেট

নতুন ফাইলগুলো আপলোড করুন, তবে **`config.php` বদলাবেন না**। তারপর `https://আপনার-ডোমেইন/install.php` খুলুন: ইনস্টলার দেখবে সাইট আগেই ইনস্টল করা, অ্যাডমিনের ইমেইল-পাসওয়ার্ড চাইবে, তারপর নতুন টেবিল/কলাম যোগ করে নিজেকে মুছে ফেলবে। পুরনো সব ডেটা থাকে। নিচের প্রতিটা আপডেটে "setup.php চালান" মানে এখন এই ধাপটাই।

**প্রোফাইল ছবির আপডেট:** `install.php` দিয়ে ডেটাবেস আপডেট করলে `users` টেবিলে `avatar` কলাম যোগ হবে। `media/` ফোল্ডার তার `.htaccess` সহ আপলোড করুন। cPanel File Manager অনেক সময় dot-ফাইল লুকিয়ে রাখে, Settings → Show Hidden Files চালু করে দেখে নিন `.htaccess` গেছে কিনা।

**ইমেইল, রেফারেল আর সাপোর্ট বাটনের আপডেট:** নতুন ফাইল আপলোড করে `install.php` দিয়ে ডেটাবেস আপডেট করুন। এতে `email_otps`, `email_log`, `referrals`, `payouts` টেবিল আর `users`/`orders`-এ নতুন কলাম যোগ হবে। `config.php` বদলাতে হবে না।

**ডোমেইন আর গেটওয়ের কাগজের আপডেট:** `install.php` দিয়ে ডেটাবেস আপডেট করুন। এতে `orders`-এ `domain` কলাম, `files`-এ লাইসেন্স/NID ধরন, আর `domain_cache`, `domain_searches` টেবিল যোগ হবে।

**সব প্যাকেজে ডোমেইন আর শুধু PayStation-এর আপডেট:** `install.php` দিয়ে ডেটাবেস আপডেট করুন (`domain_cache`-এ `source` কলাম যোগ হবে)। অ্যাডমিন প্যানেল থেকে আগে প্যাকেজ সেভ করা থাকলেও কিছু করতে হবে না: প্রথমবার পেজ খুললেই সেভ করা ক্যাটালগ নিজে থেকে নতুন নিয়মে আসে।
- ডোমেইন ছাড়া প্যাকেজে ডোমেইন ও হোস্টিং যোগ হয়, `.com` ছাড়া।
- বিকাশ/SSLCommerz অ্যাড-অন মুছে যায়।
- গেটওয়ে অ্যাড-অনের নাম হয় "Automated Payment Gateway - PayStation"।

**SEO আপডেট:** নতুন `index.php`, `seo.php`, `.htaccess` আর `assets/og-card.jpg` সহ সব ফাইল আপলোড করুন (`config.php` বাদে)। ডেটাবেসে কোনো বদল নেই, তাই `install.php` লাগবে না। তারপর অ্যাডমিন → SEO ও সোশ্যাল কার্ড → "লাইভ সাইট চেক করুন"।

`.htaccess`-এ এখন html/js/json ফাইলে `Cache-Control: no-cache` আছে, আর পেজগুলো `api.js?v=…` দিয়ে লোড হয়। তাই আপডেটের পর ব্রাউজার পুরনো কপি দেখায় না।

**ডোমেইন সার্চে সব "অজানা" দেখালে:** অ্যাডমিন → প্যাকেজ ও দাম → ডোমেইন এক্সটেনশন → "লাইভ ডোমেইন চেক টেস্ট করুন" চাপুন। এটা দেখায় সার্ভার আর ব্রাউজার রেজিস্ট্রি (Verisign, CentralNic) আর DNS-এ (Google, Cloudflare) পৌঁছাতে পারছে কিনা। সার্ভারের সব লাইন লাল হলে হোস্টিং প্রোভাইডারকে বাইরের HTTPS (port 443) কল চালু করতে বলুন।

## সাইট সেটিং (অ্যাডমিন → সাইট সেটিং)

কোড না ছুঁয়েই সাইটের চেহারা আর তথ্য বদলান:
- **ফেভিকন:** বর্গাকার PNG/JPG/WebP (৫১২×৫১২ সবচেয়ে ভালো) আপলোড করুন। সার্ভার ৩২ আর ১৯২ পিক্সেলের আইকন বানিয়ে `media/`-তে রাখে, হোমপেজ, ড্যাশবোর্ড আর অ্যাডমিন সব জায়গায় বসে। "ডিফল্টে ফেরান" দিলে Techill-এর আইকন ফিরে আসে। ছবি ছোট করতে PHP GD লাগে।
- **হোমপেজের লেখা:** উপরের ছোট লেখা, শিরোনাম আর তার নীল অংশ, নিচের লেখা, তিনটা টিক চিহ্ন, শেষের ব্যানার, ফুটারের পরিচিতি।
- **যোগাযোগ:** WhatsApp (দিলে সাইটের সব WhatsApp বাটন এটাতে যায়), ফোন, ইমেইল, খোলার সময়, ঠিকানা, Facebook/Instagram/YouTube। ফুটারে শুধু পূরণ করা তথ্যগুলোই দেখায়।
- **ইনভয়েস:** প্রতিষ্ঠানের নাম আর নিচের নোট। ঠিকানা, ফোন আর ইমেইল যোগাযোগের তথ্য থেকে আসে। "নমুনা ইনভয়েস দেখুন" দিয়ে সেভের আগেই দেখে নিন।
- **ব্র্যান্ড:** সাইটের নাম। Google-এর টাইটেল আর বিবরণ এখন "SEO ও সোশ্যাল কার্ড" সেকশনে।

লেখা ফাঁকা রাখলে আগের ডিফল্ট লেখাই দেখায়।

## SEO ও সোশ্যাল কার্ড (অ্যাডমিন → SEO ও সোশ্যাল কার্ড)

হোমপেজ এখন `index.php` দিয়ে খোলে। সে `index.html`-এর `<!--seo-->` অংশে অ্যাডমিনের দেওয়া সব ট্যাগ বসিয়ে দেয়, তাই Google, Facebook, WhatsApp JavaScript না চালিয়েই সঠিক টাইটেল, বিবরণ আর ছবি পায়। `.htaccess` `index.html`, `/robots.txt` আর `/sitemap.xml`-কে `index.php`/`seo.php`-এ পাঠায়।

- **Google সার্চ রেজাল্ট:** সাইটের ঠিকানা (canonical), টাইটেল, বিবরণ (অক্ষর গোনার কাউন্টার সহ), কি-ওয়ার্ড, ব্যবসার ধরন, আর "Google-এ দেখান" সুইচ (বন্ধ করলে `noindex` আর robots.txt-এ `Disallow: /`)।
- **structured data:** ব্যবসার নাম, লোগো, ফোন, ইমেইল, ঠিকানা, সোশ্যাল লিংক আর প্রতিটা প্যাকেজের দাম schema.org JSON-LD হিসেবে নিজে থেকেই যায়।
- **সোশ্যাল শেয়ার:** Open Graph আর X (Twitter) কার্ড। আলাদা শেয়ার টাইটেল/বিবরণ, ছবির বর্ণনা, X username, Facebook App ID। নিজের ছবি দিলে মাঝখান থেকে ১২০০×৬৩০ কেটে JPG করে রাখে (PHP GD লাগে)।
- **সোশ্যাল কার্ড মেকার:** ৪টা ডিজাইন, ৬টা রং বা নিজের রং, শিরোনাম, রঙিন অংশ, ব্যাজ, ওয়েবসাইটের ঠিকানা, লোগো আর স্টোর স্ক্রিনশট। তিন মাপ: শেয়ার কার্ড ১২০০×৬৩০ (এক ক্লিকে শেয়ার ছবি হিসেবে বসে), ফেসবুক পোস্ট ১০৮০×১০৮০, স্টোরি ১০৮০×১৯২০ (PNG ডাউনলোড)। শেয়ার কার্ড JPG হিসেবে সেভ হয়, কারণ WhatsApp ৩০০KB-এর বড় ছবিতে প্রিভিউ দেখায় না।
- **লাইভ প্রিভিউ:** Google, Facebook, WhatsApp আর X-এ লিংক কেমন দেখাবে, টাইপ করতে করতেই।
- **SEO স্কোর:** ৯টা চেকের তালিকা, কী বাকি আর কীভাবে ঠিক করবেন। "লাইভ সাইট চেক করুন" ব্রাউজার থেকে হোমপেজ, robots.txt আর sitemap.xml খুলে দেখে সার্ভার সত্যিই ট্যাগগুলো পাঠাচ্ছে কিনা।
- **ভেরিফিকেশন ও অ্যানালিটিক্স:** Google Search Console, Bing Webmaster, Facebook ডোমেইন ভেরিফিকেশন (পুরো `<meta>` ট্যাগ পেস্ট করলেও চলে), GA4 আর Tag Manager ID, আর অ্যাডভান্সড অংশে `<head>`-এ নিজের কোড।
- **IndexNow:** "এখনই জানান" Bing, Yandex, Naver আর Seznam-কে পেজ আপডেটের খবর দেয়। কী-ফাইল `seo.php?f=indexnow`। Google ping নেয় না, Google-এর জন্য Search Console-এ sitemap জমা দিন।

**Google-এ ইনডেক্স করার ধাপ:**
1. অ্যাডমিনে "সাইটের ঠিকানা"-তে নিজের ডোমেইন (https সহ) দিয়ে সেভ করুন।
2. [Search Console](https://search.google.com/search-console) → URL prefix-এ ঠিকানা দিন → HTML tag → কোডটা "Google Search Console কোড" ঘরে দিয়ে সেভ → Verify।
3. Search Console → Sitemaps → `https://আপনার-ডোমেইন/sitemap.xml` Submit।
4. URL Inspection-এ হোমপেজের ঠিকানা দিয়ে "Request indexing"। সাধারণত ২ থেকে ৭ দিনে আসে।
5. শেয়ার ছবি বদলালে [Facebook Sharing Debugger](https://developers.facebook.com/tools/debug/)-এ "Scrape Again" চাপুন, না হলে Facebook পুরনো ছবি দেখাতে থাকে।

robots.txt অ্যাডমিন, ড্যাশবোর্ড, `api.php`, `install.php` আর `uploads/` ক্রল করতে মানা করে। `admin.html` আর `dashboard.html`-এ `noindex` আছে। sitemap.xml বা robots.txt না খুললে দেখুন `.htaccess` আর `seo.php` আপলোড হয়েছে কিনা আর হোস্টে mod_rewrite চালু আছে কিনা (cPanel-এ সাধারণত থাকে)।

## ইনভয়েস ও PDF

- **কাস্টমার:** ড্যাশবোর্ড → প্রোজেক্টে "ইনভয়েস দেখুন", অথবা অর্ডার তালিকায় "ইনভয়েস"।
- **অ্যাডমিন:** অর্ডারের ড্রয়ারে "ইনভয়েস"। একই ইনভয়েস, একই ডিজাইন।
- ইনভয়েসে লোগো, প্রতিষ্ঠানের তথ্য, বিল প্রাপক, প্রোজেক্ট (ডোমেইন সহ), প্রতিটা লাইন, ছাড়, মোট, পেমেন্টের তথ্য আর পরিশোধিত/যাচাই বাকি/বাতিল সিল থাকে।
- **PDF ডাউনলোড:** বাটন চাপলে A4 PDF সরাসরি ডাউনলোড হয় (`invoice-TC-XXXX.pdf`)। এর জন্য ব্রাউজার একবার cdnjs থেকে html2pdf.js আনে। বাংলা লেখা ব্রাউজার যেভাবে দেখায় ঠিক সেভাবেই ছবি হিসেবে PDF-এ যায়, তাই যুক্তাক্ষর ভাঙে না, তবে PDF-এর লেখা কপি করা যায় না। ইন্টারনেট না থাকলে প্রিন্টের ঘর খোলে, সেখান থেকে "Save as PDF"।

## অনলাইন পেমেন্ট (PayStation)

admin.html → **পেমেন্ট গেটওয়ে**:

1. **Sandbox** বেছে PayStation-এর Sandbox Merchant ID আর পাসওয়ার্ড দিন, **অনলাইন পেমেন্ট চালু** করে সেভ করুন, তারপর **সংযোগ পরীক্ষা** চাপুন।
2. সাইট থেকে একটা ছোট অর্ডার দিয়ে পুরো পেমেন্ট করে দেখুন। ঠিক থাকলে অর্ডার নিজে থেকেই "যাচাই হয়েছে" হবে আর কাউন্টডাউন শুরু হবে।
3. সব ঠিক থাকলে **Live** বেছে Live-এর তথ্য দিয়ে সেভ করুন।
4. বন্ধ করতে চাইলে সুইচ বন্ধ করে সেভ করুন। তখন চেকআউটে শুধু ম্যানুয়াল Send Money দেখাবে। ম্যানুয়ালও আলাদা করে বন্ধ করা যায়, তবে দুটো একসাথে বন্ধ করা যায় না।

**কীভাবে কাজ করে:**
- কাস্টমার চেকআউটে "অনলাইনে পেমেন্ট" বেছে তথ্য জমা দিলে অর্ডার সেভ হয়, আর সার্ভার PayStation-এর `initiate-payment` থেকে পেমেন্ট লিংক নিয়ে কাস্টমারকে সেখানে পাঠায়।
- পেমেন্ট শেষে PayStation কাস্টমারকে `api.php?action=paystation_callback`-এ ফেরত পাঠায়। সার্ভার তখন নিজে PayStation-এর `transaction-status` থেকে আসল অবস্থা জেনে নেয়।
- ব্রাউজার যা বলে তা বিশ্বাস করা হয় না। ইনভয়েস নম্বর আর টাকার পরিমাণ না মিললে অর্ডার নিশ্চিত হয় না, আর একই পেমেন্ট দুবার গোনা হয় না।
- সফল হলে অর্ডার "যাচাই হয়েছে" হয়, TrxID বসে, চ্যাটে কাস্টমার মেসেজ পান, আর **ডেলিভারির কাউন্টডাউন পেমেন্টের সময় থেকে শুরু হয়।**
- পেমেন্ট বাতিল বা ব্যর্থ হলে কাস্টমার ড্যাশবোর্ড থেকে **অনলাইনে পেমেন্ট করুন** চেপে আবার চেষ্টা করতে পারেন। প্রতিবার নতুন ইনভয়েস নম্বর যায়, কারণ PayStation পুরনো নম্বর আবার নেয় না।
- কেউ টাকা দিয়ে আর ফিরে না এলে, পরের বার পেমেন্ট শুরু করার আগে সেটা ধরা পড়ে। অ্যাডমিন অর্ডারের ড্রয়ার থেকে **PayStation থেকে আবার যাচাই করুন**-ও চাপতে পারেন।
- পাসওয়ার্ড ডেটাবেসে থাকে, কখনো ব্রাউজারে পাঠানো হয় না।

**দরকার:** সার্ভারে PHP cURL চালু থাকতে হবে (বেশিরভাগ cPanel-এ থাকে), আর সাইট HTTPS-এ থাকতে হবে। PayStation অনেক সময় মার্চেন্ট সার্ভারের IP হোয়াইটলিস্ট করতে বলে। cPanel-এর IP ওদের দিন।

**মনে রাখবেন:** এই ইন্টিগ্রেশন PayStation-এর প্রকাশিত API (`initiate-payment`, `transaction-status`) অনুযায়ী বানানো, কিন্তু আসল PayStation সার্ভারে পরীক্ষা করা হয়নি। Live চালুর আগে Sandbox-এ অন্তত একটা সফল আর একটা বাতিল পেমেন্ট করে দেখুন।

## Facebook Pixel

অ্যাডমিন প্যানেল → **Facebook Pixel**। কোড বসাতে হবে না।

1. Meta Events Manager → Data sources → আপনার Pixel → Settings থেকে **Pixel ID** (শুধু সংখ্যা) কপি করে বসান, **Pixel চালু** করে সেভ করুন।
2. **Conversions API** (ঐচ্ছিক, তবে দরকারি): একই Settings পেজে "Generate access token" থেকে token নিয়ে বসান। iPhone আর অ্যাড ব্লকারে ব্রাউজারের Pixel অনেক সময় আটকে যায়, তখন সার্ভার নিজেই Meta-কে Purchase জানায়।
3. পরীক্ষা: Events Manager → Test events থেকে **test event code** নিয়ে বসান, **টেস্ট ইভেন্ট পাঠান** চাপুন। কাজ হলে **কোডটা মুছে সেভ করুন**, নাহলে সার্ভারের ইভেন্ট Ad-এর হিসাবে যাবে না।

যে ইভেন্টগুলো যায়: `PageView`, `InitiateCheckout` (প্যাকেজ বাছলে), `AddPaymentInfo`, `Purchase` (অর্ডার জমা বা অনলাইন পেমেন্ট সফল হলে, অর্ডার কোড event ID হিসেবে, তাই ব্রাউজার আর সার্ভারের Purchase দুবার গোনা হয় না), `Contact` (হোয়াটসঅ্যাপ ক্লিক)। সব টাকা BDT-তে।

- Token সেভ হওয়ার পর আর ব্রাউজারে ফেরত দেখানো হয় না। বদলাতে নতুনটা দিন, বা **Token মুছুন** চাপুন।
- সার্ভারের শেষ পাঠানোটা সফল না ব্যর্থ, প্যানেলেই দেখা যায়। Meta ভুল token বললেও অর্ডার আটকায় না।
- সার্ভার ইমেইল আর ফোন SHA-256 hash করে পাঠায়, আসল লেখা না।
- Meta Graph API ভার্সন `lib.php`-এর `FB_GRAPH_VERSION` (এখন `v21.0`)। Meta পুরনো ভার্সন বন্ধ করলে এটা বদলাতে হবে।
- আসল Meta সার্ভারে পরীক্ষা করা হয়নি। চালুর পর Test events-এ একটা ইভেন্ট দেখে নিন।

## ছবি

- **টেমপ্লেটের ছবি:** অ্যাডমিন → প্যাকেজ ও দাম → টেমপ্লেট টেবিলের ছবি কলাম থেকে আপলোড, তারপর **সেভ** চাপুন। চেকআউটের ১ম ধাপে নকশার বদলে এই ছবি দেখায়। ৪:৫ মাপের (যেমন 800×1000) স্ক্রিনশট সবচেয়ে ভালো দেখায়।
- **প্রোফাইল ছবি:** কাস্টমার আর ডেভেলপার ড্যাশবোর্ডের উপরে নিজের নামে চাপ দিয়ে বদলাতে পারেন। অ্যাডমিন যে কারো ছবি তাদের ড্রয়ার থেকে বদলাতে পারেন, নিজেরটা উপরের গোল ছবিতে চাপ দিয়ে। ছবি চ্যাট, টিম আর কাস্টমার তালিকায় দেখায়।
- সার্ভার প্রতিটা ছবি আবার নতুন করে বানায় (webp, প্রোফাইল 320px, টেমপ্লেট সর্বোচ্চ 1200px), ফলে ছবির ভেতরে লুকানো কোড বা লোকেশন তথ্য থাকে না। সর্বোচ্চ ৫ MB। PHP-তে GD extension লাগে (cPanel-এ সাধারণত চালু)।

## চেকআউটের ডোমেইন ধাপ

চেকআউট এখন ৬ ধাপের: টেমপ্লেট → অ্যাড-অন → পেমেন্ট → তথ্য → **ডোমেইন** → কাউন্টডাউন।

- **কী দেখায়:** কাস্টমার নাম লিখে খোঁজেন। প্যাকেজে যতগুলো এক্সটেনশন পাওয়া যায়, প্রতিটার পাশে "খালি আছে", "নেওয়া হয়ে গেছে" বা "অজানা" দেখায়। প্রথম খালিটা নিজে থেকে বাছাই হয়ে যায়। কিছুই খালি না পেলে নামের কয়েকটা বিকল্প দেখায়।
- **সব প্যাকেজে ডোমেইন ও হোস্টিং আছে।** Starter আর Lite পায় `.shop .top .store .online .site .website`। Business, Pro, Growth আর Ultimate এগুলোর সাথে `.com`-ও পায়।
  - অ্যাডমিন → প্যাকেজ ও দাম → "ডোমেইন এক্সটেনশন" থেকে তালিকা বদলানো যায়।
  - প্রতিটা প্যাকেজে ".com সহ" টিক দিয়ে ঠিক করা যায় কোন প্যাকেজ দ্বিতীয় তালিকা পাবে।
- **কোনো প্যাকেজ থেকে ডোমেইন সরিয়ে দিলে:** কাস্টমার "ডোমেইন যোগ করুন" চেপে অ্যাড-অন নিতে পারেন। Send Money আগে করা থাকলে তাকে পেমেন্ট ধাপে ফেরত পাঠানো হয়, যাতে নতুন মোট টাকা দেখেন। চাইলে "আমার ডোমেইন আছে" বা "পরে ঠিক করব"-ও বাছতে পারেন।
- **প্রোজেক্টের নাম:** ডোমেইন ঠিক হলে ড্যাশবোর্ড আর অ্যাডমিন প্যানেলের সব জায়গায় অর্ডার কোডের বদলে ডোমেইনটাই প্রোজেক্টের নাম হিসেবে দেখায়। কোডটা ছোট করে পাশে থাকে। ডেভেলপার আপডেট ফর্ম থেকে ডোমেইন বদলানোও যায়।
- **কীভাবে খোঁজে (লাইভ, ফ্রি, কোনো API key লাগে না):**
  1. প্রথমে সরাসরি রেজিস্ট্রির RDAP সার্ভারে জিজ্ঞেস করে, যেমন .com-এর জন্য Verisign। এটাই সবচেয়ে নির্ভরযোগ্য উত্তর। কোন এক্সটেনশন কোন সার্ভারে, সেটা IANA-র তালিকা থেকে নেয়, আর তালিকাটা সপ্তাহে একবার নতুন করে আনে।
  2. রেজিস্ট্রি সাড়া না দিলে Google আর Cloudflare-এর ফ্রি DNS-over-HTTPS দিয়ে দেখে। এই উত্তরের পাশে "DNS অনুযায়ী খালি" লেখা থাকে।
  3. সার্ভার থেকেও উত্তর না পেলে (কিছু হোস্ট বাইরে কল আটকায়) কাস্টমারের ব্রাউজার নিজেই একই জায়গাগুলোতে জিজ্ঞেস করে।
  - সব এক্সটেনশন একসাথে খোঁজা হয়। উত্তর মাত্র ৩ মিনিট মনে রাখে, আর পাশে "লাইভ যাচাই · সময়" আর "আবার চেক করুন" থাকে।
  - একজন ঘণ্টায় ৬০ বার খুঁজতে পারে।
  - আরেকটা চালু অর্ডারে যে ডোমেইন বাছা হয়েছে, সেটা পরের কাস্টমারের কাছে "বুক করা" দেখায়, আর জমা দেওয়া যায় না।
  - ডেমো বা স্ট্যাটিক প্রিভিউতে (PHP ছাড়া) ব্রাউজার থেকেই আসল রেজিস্ট্রি আর DNS-এ খোঁজে, বানানো ফল দেখায় না।
  - সার্ভারে PHP cURL লাগবে।
  - শুধু ইংরেজি অক্ষর, সংখ্যা আর হাইফেন চলে। বাংলা ডোমেইন নেওয়া হয় না।
- **মনে রাখবেন:** ডোমেইন নিজে থেকে কেনা হয় না, অ্যাডমিন রেজিস্ট্রার থেকে কিনবেন।
  - "খালি আছে" দেখালেও প্রিমিয়াম দামের ডোমেইন হতে পারে, বা মাঝখানে অন্য কেউ কিনে নিতে পারে। কাস্টমারকে সেটা বলা আছে।
  - অর্ডার জমার সময় সার্ভার cache ছাড়া আবার লাইভ যাচাই করে, নেওয়া হয়ে গেলে আরেকটা বাছতে বলে।
  - DNS-এর উত্তর ১০০% নিশ্চিত না, কারণ নেমসার্ভার ছাড়া রেজিস্টার করা ডোমেইনও "খালি" দেখাতে পারে। তাই রেজিস্ট্রি সাড়া দিলে সেটাই আগে নেওয়া হয়।
  - রেজিস্ট্রি সাড়া না দিলে "অজানা" দেখায়, তবু বাছা যায়।

## পেমেন্ট গেটওয়ের কাগজপত্র

অর্ডারে পেমেন্ট গেটওয়ে থাকলে তথ্য ধাপে আলাদা একটা ঘর আসে। গেটওয়ে প্যাকেজে থাকতে পারে (যেমন Pro, Growth, Ultimate), অথবা "PayStation পেমেন্ট গেটওয়ে" অ্যাড-অন নেওয়া হতে পারে। গেটওয়ে হিসেবে শুধু PayStation দেওয়া হয়, কারণ বিকাশ, নগদ, রকেট আর কার্ড সবই এর ভেতরে আছে। ঘরে চারটা জিনিস চাওয়া হয়:
- ট্রেড লাইসেন্স নম্বর
- ট্রেড লাইসেন্সের ছবি বা PDF
- NID নম্বর (১০, ১৩ বা ১৭ ডিজিট)
- NID কার্ডের ছবি বা PDF

পাশে লেখা থাকে যে গেটওয়ে রেজিস্ট্রেশনের জন্যই এগুলো লাগবে। সবগুলো বাধ্যতামূলক।

- **ফাইল:** শুধু JPG, PNG, WebP বা PDF নেওয়া হয়। সার্ভার ফাইলের আসল ধরন মিলিয়ে দেখে।
- **কে দেখতে পায়:** অ্যাডমিন অর্ডারের ড্রয়ারে "পেমেন্ট গেটওয়ের কাগজপত্র" বাক্সে নম্বর দুটো দেখেন, ফাইল খুলতেও পারেন। ফাইল শুধু লগইন করা অ্যাডমিন, সেই প্রোজেক্টের ডেভেলপার আর কাস্টমার নিজে খুলতে পারেন।
- **কাস্টমার পরে বদলাতে পারেন:** নম্বর তথ্য ট্যাব থেকে, আর নতুন ছবি ফাইল ট্যাব থেকে।
- **গুরুত্বপূর্ণ:** NID ব্যক্তিগত তথ্য। `config.php`-তে `upload_dir` public_html-এর বাইরে রাখুন, যেমন `/home/cpaneluser/techill_uploads`। গেটওয়ে চালু হয়ে গেলে দরকার না থাকলে ফাইলগুলো মুছে ফেলার কথা ভাবুন।

## ইমেইল (SMTP)

অ্যাডমিন প্যানেল → **ইমেইল**। এখান থেকে তিনটা কাজ হয়:
- **OTP:** নতুন অ্যাকাউন্টে ইমেইল যাচাই, "পাসওয়ার্ড ভুলে গেছেন", আর প্রোফাইল থেকে ইমেইল যাচাই বা বদলানো। কোড ৬ ডিজিটের, ১০ মিনিট কাজ করে, ৫ বার ভুল দিলে বাতিল হয়। একই ইমেইলে মিনিটে একটা আর ঘণ্টায় ৫টা কোড যায়।
- **নোটিফিকেশন:**
  - নতুন অর্ডার এলে কাস্টমার রসিদ পান, আর অ্যাডমিনের কাছে খবর যায়।
  - প্রোজেক্টের ধাপ বদলালে, পেমেন্ট যাচাই হলে, ডেলিভারি বা বাতিল হলে কাস্টমারকে জানানো হয়।
  - চ্যাটে নতুন মেসেজ এলে অন্য পক্ষ ইমেইল পান। একই অর্ডারে ১০ মিনিটে একবারের বেশি যায় না।
  - ডেভেলপারকে প্রোজেক্ট দিলে তিনি ইমেইল পান। রেফারেলের আয় আর টাকা পাঠানো হলেও ইমেইল যায়।
  - প্রতিটা ধরন আলাদা করে বন্ধ করা যায়। কাস্টমার চাইলে নিজের প্রোফাইল থেকে অগ্রগতি আর মেসেজের ইমেইল বন্ধ করতে পারেন।
- **লগ:** কোন ইমেইল গেছে আর কোনটা যায়নি (কারণ সহ), সব প্যানেলে দেখা যায়। মেসেজের লেখা রাখা হয় না।

**সেটআপ (cPanel):**
1. cPanel → Email Accounts থেকে `noreply@আপনার-ডোমেইন` বানান।
2. সেই অ্যাকাউন্টের **Connect Devices**-এ গিয়ে Outgoing Server আর পোর্ট দেখুন। সাধারণত `mail.আপনার-ডোমেইন`, পোর্ট 465, SSL।
3. প্যানেলে **cPanel ইমেইল** বোতাম চাপুন। ইউজারনেম আর From-এ পুরো ইমেইল দিন, পাসওয়ার্ড দিন।
4. **টেস্ট ইমেইল পাঠান** চাপুন। ইমেইল এলে সুইচ চালু করে সেভ করুন।
5. cPanel → Email Deliverability-এ SPF আর DKIM "Valid" করুন, নইলে ইমেইল Spam-এ যাবে।

Gmail দিয়েও পাঠানো যায়: smtp.gmail.com, পোর্ট 587, STARTTLS, আর পাসওয়ার্ডের জায়গায় **App password** দিন।

- **"নতুন অ্যাকাউন্টে OTP বাধ্যতামূলক"** চালু থাকলে রেজিস্ট্রেশন আর চেকআউট দুই জায়গাতেই নতুন কাস্টমারকে কোড দিতে হবে। পুরনো অ্যাকাউন্টের মালিক শুধু পাসওয়ার্ড দেবেন।
- ইমেইল পাঠানো হয় পেজের উত্তর চলে যাওয়ার পর, তাই মেইল সার্ভার ধীর হলেও সাইট ধীর হয় না। এটা PHP-FPM বা LiteSpeed-এ কাজ করে, যা বেশিরভাগ cPanel-এ থাকে। অন্য সার্ভারে ইমেইল তখনই যায়, তাই একটু দেরি হতে পারে। OTP সবসময় সাথে সাথে যায়।
- SMTP পাসওয়ার্ড কখনো ব্রাউজারে ফেরত পাঠানো হয় না।
- মেইল সার্ভার যদি `localhost` হয় আর সার্টিফিকেট অন্য নামের হয়, তাহলে "সার্টিফিকেট" error আসবে। সেক্ষেত্রে আসল হোস্টনেম দিন। একান্তই না হলে `config.php`-তে `'smtp_allow_self_signed' => true,` যোগ করুন।

## সাপোর্ট বাটন

অ্যাডমিন প্যানেল → **সাপোর্ট বাটন**।

ল্যান্ডিং পেজের ডান কোণে নিচে একটা ভাসমান বাটন থাকে। চাপলে তিনটা অপশন খোলে:
- **Messenger:** পেজের username বা লিংক দিন, যেমন `techillbd` বা `facebook.com/techillbd`। ক্লিক করলে `m.me` দিয়ে Messenger খোলে। ফেসবুকের পুরনো "Chat Plugin" Meta ২০২৪-এ বন্ধ করে দিয়েছে, তাই এটাই এখন একমাত্র উপায়।
- **WhatsApp:** ফোনে WhatsApp অ্যাপ খোলে (`wa.me`), কম্পিউটারে সরাসরি WhatsApp Web। মেসেজ আগে থেকে লেখা থাকে। নম্বর খালি রাখলে প্যাকেজ ও দাম পেজের নম্বর ব্যবহার হয়।
- **লাইভ চ্যাট (tawk.to):**
  - tawk.to-তে ফ্রি অ্যাকাউন্ট খুলুন। তারপর Administration → Chat Widget থেকে **Direct Chat Link** বা পুরো widget কোড কপি করে পেস্ট করুন।
  - বাটন প্রথমবার খোলার পরই tawk.to লোড হয়, তাই পেজ ধীর হয় না।
  - tawk.to-এর নিজের বাটন লুকানো থাকে। লগইন করা কাস্টমারের নাম আর ইমেইল চ্যাটে আগে থেকে বসে যায়।

কোন মাধ্যমে কতজন ক্লিক করেছে প্যানেলে দেখা যায়। প্রতিটা ক্লিক Pixel-এ `Contact` ইভেন্ট হিসেবেও যায়। চাইলে কাস্টমার ড্যাশবোর্ডেও বাটনটা দেখানো যায়।

## রেফারেল

- **কাস্টমার দেখেন:** ড্যাশবোর্ডে **রেফার করে আয়** ট্যাব হাইলাইট করা থাকে। সেখানে নিজের কোড, লিংক (`index.html?ref=CODE`), WhatsApp/Facebook-এ শেয়ার বোতাম, ব্যালেন্স, প্রতিটা রেফারেলের অবস্থা, আর বিকাশ/নগদ/রকেটে টাকা তোলার ফর্ম।
- **বন্ধু যা পান:** লিংকে ঢুকলে উপরে লেখা আসে "রাকিব আপনাকে ৳১,০০০ ছাড় দিয়েছেন"। কোডটা ৩০ দিন মনে থাকে, চেকআউটে ছাড় নিজে থেকে বসে যায়। চেকআউটে হাতে কোড লেখারও ঘর আছে।
- **ডিফল্ট নিয়ম (প্যানেল থেকে বদলানো যায়):**
  - রেফারার পান ৳১,০০০, নতুন কাস্টমার পান ৳১,০০০ ছাড়।
  - ছাড় শুধু ৳৫,০০০ বা তার বেশি অর্ডারে, আর নতুন কাস্টমারের প্রথম অর্ডারে।
  - আয় যোগ হয় পেমেন্ট যাচাই হয়ে ওয়েবসাইট **ডেলিভারি হলে**। চাইলে "পেমেন্ট যাচাই হলেই" করা যায়।
  - ৳১,০০০ জমলে টাকা তোলা যায়।
- **নিরাপত্তা:**
  - দাম আর ছাড় সার্ভারে হিসাব হয়।
  - নিজের কোড নিজে ব্যবহার করা যায় না, ইমেইল আর ফোন নম্বর মিলিয়ে দেখা হয়।
  - অর্ডার বাতিল হলে বা পেমেন্ট না এলে আয় যোগ হয় না।
  - ইমেইল চালু থাকলে টাকা তুলতে যাচাই করা ইমেইল লাগে। একসাথে একটার বেশি অনুরোধ করা যায় না।
- **অ্যাডমিন:** প্যানেল → **রেফারেল**। টাকা পাঠিয়ে TrxID দিয়ে "পাঠিয়েছি" চাপুন, কাস্টমার ইমেইল পাবেন। সন্দেহজনক রেফারেল বাতিল করা যায়, পরে ফিরিয়েও আনা যায়। নতুন অনুরোধ এলে ওভারভিউতে সতর্কবার্তা দেখায়।

## অ্যাডমিন প্যানেল

- **ওভারভিউ:** কী করতে হবে তার তালিকা (পেমেন্ট যাচাই বাকি, ডেভেলপার দেওয়া হয়নি, ডেডলাইন পেরিয়েছে, না-পড়া মেসেজ)। এখন কতজন সাইটে আছে, আজকের ও মোট ভিজিটর, কনভার্শন, আয়, বাকি পেমেন্ট, দৈনিক চার্ট, ভিজিটর থেকে অর্ডার পর্যন্ত funnel, প্রোজেক্ট পাইপলাইন, টিমের কাজের চাপ আর সাম্প্রতিক কার্যকলাপ।
- **অর্ডার:** ফিল্টার, সার্চ, সরাসরি ডেভেলপার অ্যাসাইন আর CSV এক্সপোর্ট (Excel-এ বাংলা ঠিক দেখায়)। কোনো অর্ডারে ক্লিক করলে পাশে ড্রয়ার খোলে। সেখানে এক ক্লিকে পেমেন্ট যাচাই, অতিরিক্ত চার্জ বা ছাড়, ডেডলাইন বাড়ানো, বাতিল বা আবার চালু করা আর হোয়াটসঅ্যাপে কাস্টমারকে মেসেজ করা যায়।
- **প্রোজেক্ট বোর্ড:** ধাপ অনুযায়ী কলাম, ডেভেলপার দিয়ে ফিল্টার। যেগুলোর দেরি হচ্ছে সেগুলো লাল দেখায়।
- **ওভারভিউয়ের উপরে:** মোট কাস্টমার, ডেভেলপার, প্যাকেজ আর ভিজিটরের সংখ্যা। ক্লিক করলে সেই অংশে চলে যায়।
- **অ্যানালিটিক্স** (৭ দিন / ৩০ দিন / ৯০ দিন / ১ বছর):
  - **ভিজিটর:** এখন কে সাইটে আছে (শহর, পেজ, ডিভাইস), আগের সময়ের তুলনায় কম না বেশি, নতুন আর ফিরে আসা ভিজিটর, bounce, দেশ, শহর, বিভাগ, দিনের কোন সময়ে আর সপ্তাহের কোন দিনে বেশি আসে, ডিভাইস, ব্রাউজার (Facebook অ্যাপের ভেতরের ব্রাউজার আলাদা দেখায়), অপারেটিং সিস্টেম, রেফারার, `utm_source` আর পেজ।
  - **অর্ডার:** সংখ্যা ও তুলনা, কনভার্শন, সময়মতো ডেলিভারির হার, গড় ডেলিভারি সময়, বাতিলের হার, চেকআউট খুলে চলে যাওয়া ভিজিটর, প্যাকেজ, প্ল্যাটফর্ম, পেমেন্ট মাধ্যম, আর **অর্ডারগুলো কোন সোর্স থেকে এসেছে** (কাস্টমারের প্রথম ভিজিট ধরে)।
  - **আয়:** সময়সীমার আয় ও তুলনা, এই মাস বনাম গত মাস, শুরু থেকে মোট, বাকি পেমেন্ট, গত ১২ মাসের মাসিক আয়, দৈনিক আয়, প্যাকেজ আর পেমেন্ট মাধ্যম অনুযায়ী আয়, আর যারা সবচেয়ে বেশি দিয়েছেন।
  - Facebook Ad লিংকের শেষে `?utm_source=fb_ads` দিলে কোন Ad থেকে কতজন এসেছে আর কতগুলো অর্ডার হয়েছে, আলাদা দেখা যাবে।
- **প্যাকেজ ও দাম:** প্যাকেজ, দাম, ডেলিভারির সময়, ফিচার, কী ফ্রি, টেমপ্লেট, অ্যাড-অন আর পেমেন্ট নম্বর, সব কোড না ছুঁয়ে বদলানো যায়।
- **টিম ও ডেভেলপার:** যোগ করা, নাম/ইমেইল এডিট, রোল বদলানো, বন্ধ করা, পাসওয়ার্ড রিসেট আর মুছে ফেলা। মুছে ফেললে তার চলমান প্রোজেক্টগুলো অ্যাসাইন ছাড়া হয়ে যায়, অর্ডার পেজ থেকে নতুন ডেভেলপার দিতে হয়। নিজেকে বা শেষ অ্যাডমিনকে মোছা যায় না।
- **কাস্টমার:** যোগ করা, এডিট, বন্ধ বা চালু করা, পাসওয়ার্ড রিসেট আর মুছে ফেলা। ফিল্টার দিয়ে দেখা যায় কার প্রোজেক্ট চলছে, কে একাধিকবার অর্ডার করেছেন আর কে অর্ডার করেননি। **যে কাস্টমারের অর্ডার আছে তাকে মোছা যায় না**, কারণ তাতে অর্ডার, চ্যাট আর ফাইল সব হারিয়ে যেত। তার বদলে অ্যাকাউন্ট বন্ধ করুন।

## কীভাবে কাজ করে

- **কাস্টমার:** checkout-এর ৪ নম্বর ধাপে ইমেইল আর পাসওয়ার্ড দিলে অ্যাকাউন্ট খুলে যায়। আগে থেকে অ্যাকাউন্ট থাকলে সেই পাসওয়ার্ড দিলে অর্ডারটা ওই অ্যাকাউন্টেই যোগ হয়। কাস্টমার লগইন করা থাকলে পাসওয়ার্ডের ঘর দেখায় না।
- **ড্যাশবোর্ড:** কাউন্টডাউন, অগ্রগতির % আর ৫টা ধাপ (তথ্য জমা → পেমেন্ট যাচাই → সেটআপ চলছে → রিভিউ → ডেলিভারি) দেখায়। ট্যাবগুলো হলো চ্যাট, অগ্রগতির টাইমলাইন, ফাইল আর তথ্য।
- **ডেভেলপার:** ইনস্টলারে বানানো অ্যাকাউন্ট দিয়ে `dashboard.html`-এ লগইন করলে সব অর্ডার দেখা যায়। সেখান থেকে ধাপ, %, পেমেন্ট স্ট্যাটাস, সাইটের লিংক আর নোট আপডেট করা যায়, আর কাস্টমারের সাথে চ্যাট করা যায়।
- **চ্যাট:** প্রতি ৫ সেকেন্ডে নতুন মেসেজ আনে (polling)। শেয়ার্ড হোস্টিংয়ে WebSocket লাগে না। না-পড়া মেসেজের সংখ্যা অর্ডার লিস্টে দেখায়।
- **নিরাপত্তা:** `password_hash` দিয়ে পাসওয়ার্ড রাখা হয়। সব query prepared statement। POST-এ CSRF token লাগে। একই IP থেকে ১৫ মিনিটে ১০ বার ভুল লগইন হলে লক হয়ে যায়। কাস্টমার শুধু নিজের অর্ডার দেখতে পারে। ফাইল শুধু লগইন করে ডাউনলোড করা যায়, আর `.php`-এর মতো বিপজ্জনক ফাইল নেওয়া হয় না।

## জেনে রাখুন

- **দাম সার্ভারে হিসাব হয়:** ব্রাউজার শুধু জানায় কোন প্যাকেজ আর কোন অ্যাড-অন বাছাই হয়েছে। দাম `api.php` নিজে ক্যাটালগ থেকে হিসাব করে, তাই কেউ ব্রাউজারে দাম কমিয়ে অর্ডার দিতে পারবে না। তবু পেমেন্ট "যাচাই হয়েছে" করার আগে বিকাশ/নগদে আসলে কত টাকা এসেছে মিলিয়ে নিন।
- **ইমেইল আর tawk.to আসল সার্ভারে পরীক্ষা হয়নি:** নিজের বানানো টেস্ট SMTP সার্ভারে (SSL, STARTTLS, ভুল পাসওয়ার্ড) আর tawk.to-এর নকল স্ক্রিপ্টে পরীক্ষা করা হয়েছে। চালুর পর একটা টেস্ট ইমেইল পাঠিয়ে আর একবার লাইভ চ্যাট খুলে দেখে নিন।
- **ছবি খোলা লিংকে থাকে:** প্রোফাইল ও টেমপ্লেটের ছবি র‍্যান্ডম নামের লিংকে থাকে, লিংক জানলে যে কেউ দেখতে পারে। ব্যক্তিগত কিছু ছবি হিসেবে দেবেন না। টেমপ্লেটের ছবি বদলালে পুরনো ফাইল `media/`-তে থেকে যায়, চাইলে হাতে মুছুন।
- **ভিজিটর গণনা:** প্রতিটা ব্রাউজারকে একটা র‍্যান্ডম আইডি দেওয়া হয়, আর bot বাদ যায়। এটা মোটামুটি হিসাব, Google Analytics-এর মতো নিখুঁত নয়। কেউ ইচ্ছা করে ভুয়া ভিজিট পাঠাতেও পারে।
- **লোকেশন:** দেশ, শহর আর বিভাগ বের হয় ভিজিটরের IP থেকে, এই ক্রমে:
  - সাইট Cloudflare-এর পেছনে থাকলে Cloudflare-এর হেডার থেকে (সবচেয়ে ভালো, কোনো সীমা নেই)।
  - না থাকলে `config.php`-এর `geo_lookup` অনুযায়ী ipapi.co থেকে। ফ্রি প্ল্যানে দৈনিক সীমা আছে আর ব্যবসায়িক ব্যবহারের শর্ত আছে, তাই চালু রাখার আগে ওদের শর্ত দেখে নিন। একটা IP ৩০ দিনে একবারই খোঁজা হয়।
  - কিছু না পেলে ব্রাউজারের time zone থেকে শুধু দেশ।
  - IP নিজে কোথাও সেভ হয় না, শুধু `geo_salt` দিয়ে তার একটা হ্যাশ রাখা হয়। `geo_salt` একটা লম্বা এলোমেলো লেখায় বদলে দিন।
  - মোবাইল ডেটায় IP থেকে শহর প্রায়ই কাছের বড় শহর দেখায় (যেমন গাজীপুরের ভিজিটরকে ঢাকা)।
- **নোটিফিকেশন নেই:** নতুন অর্ডার বা মেসেজ এলে এখনো ইমেইল যায় না। ড্যাশবোর্ড খোলা রাখলে দেখা যায়।
